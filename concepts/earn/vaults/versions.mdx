# Vault versions (v1 and v2)

Vaults exist in two contract generations. The CMS field `vaultVersion`
selects which generation a Vault belongs to, and the UI adapts
accordingly.

**Earn V2** is the current generation. Earn V2 Vaults are asynchronous: a
withdraw transaction submits a request that is settled at the end of a
future epoch (see
[Epoch lifecycle](../withdrawals/epoch-cycle-concept)). Earn V2
introduces the concepts of epochs, queues, caps, and overflow described
elsewhere in this section. All new Vaults launch on Earn V2.

**Earn V1** is the legacy generation. Earn V1 Vaults are synchronous: a
withdraw transaction returns the underlying asset in the same call,
provided the Vault holds enough liquidity. There is no queue, no epoch,
and no cap concept. Earn V1 is no longer used for new launches and the
remaining Earn V1 deployments are being migrated forward.

Users typically do not need to think about the version. The UI surfaces
the correct deposit and withdraw affordances per Vault.

For deeper detail on the contract architecture, see the smart-contract
repository's documentation in Mintlify.
