## ConcretePredepositVaultImpl

A vault implementation that extends ConcreteStandardVaultImpl with cross-chain share claiming via a standalone OApp.

_This is useful for pre-deposit phases where users can claim their shares on a different chain.
     Withdrawals should be disabled during the predeposit phase.
     Claims can only occur when deposits and withdrawals are locked.
     Claims should only occur when underlying assets are bridged to target chain.
     Typically self claims should be enabled only when assets are already bridged to target chain.
     In claims phase shares are duplicated until claimed on target chain and burned on source chain.
     The vault uses a separate OApp contract for cross-chain messaging._

### claimOnTargetChain

```solidity
function claimOnTargetChain(bytes options) external payable
```

Burn `msg.sender`'s locked L1 shares and route the claim to the target chain via LayerZero.

_Sends a single LayerZero message reporting the caller and their eligible share amount,
     burning the L1 shares in the same call. Accrues yield first to sync strategy state;
     strategies are expected to report no yield once claims have opened. Gated by
     `selfClaimsEnabled` so individual users can only call this when self claims are enabled._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| options | bytes | LayerZero messaging options (gas/fee parameters). |

### batchClaimOnTargetChain

```solidity
function batchClaimOnTargetChain(bytes addressesData, bytes options) external payable
```

Burn locked L1 shares for a batch of users and route the claim to the target chain.

_Only callable by accounts with the VAULT_MANAGER role. Aggregates the supplied
     addresses, sends a single LayerZero message, and silently skips addresses that have
     zero claimable shares (including users who have already claimed). Accrues yield first
     so strategy accounting is synced; strategies are expected to report no yield once
     claims have opened._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| addressesData | bytes | ABI-encoded array of addresses to claim for. |
| options | bytes | LayerZero messaging options (gas/fee parameters). |

### _upgrade

```solidity

```

_Upgrade hook handling migration from `ConcreteStandardVaultImpl` to
     `ConcretePredepositVaultImpl`. Migrates any legacy admin roles to `ROLE_ADMIN` and
     defaults `selfClaimsEnabled` to false (it can later be enabled via `setSelfClaimsEnabled`)._

### _validateClaimConditions

```solidity
function _validateClaimConditions(struct ConcretePredepositVaultImplStorageLib.ConcretePredepositVaultImplStorage $) internal view
```

_Validates that a cross-chain claim can proceed: OApp address is set, deposits are
     locked (max global = 0), and withdrawals are locked (max tx = 0). The caller passes in
     the predeposit storage reference so this helper does not need to call `fetch()` again._
