## HookContainer

Container contract that combines multiple independent hook contracts into one

_Implements IHook interface and forwards all hook calls to registered sub-hooks sequentially.
     Uses ERC-7201 namespaced storage pattern for storage isolation.
     All sub-hooks must pass (no reverts) for the container hook to succeed.
Uses AccessControlDefaultAdminRulesEnumerable for role-based access control with
     default admin rules and enumeration support. HOOK_MANAGER_ROLE can add/remove sub-hooks.
IMPORTANT - Hook Order: The execution order of hooks is NOT guaranteed to remain stable.
     Adding hooks appends to the end, but removing hooks uses swap-and-pop which changes order.
     Do not rely on hook execution order for correctness. Hooks should be independently valid.
IMPORTANT - Trust Model: This container implicitly trusts all registered hook code.
     - Hooks should be stateless validators (apart from configuration storage)
     - Hooks should not allow callbacks or arbitrary code execution
     - This container intentionally provides NO reentrancy protection by design
     - All hook forwarding functions are restricted to calls from the vault via `onlyVault`
     - A malicious or buggy hook can block all vault operations
     - Thoroughly audit all hooks before registration_

### MAX_HOOKS

```solidity
uint256 MAX_HOOKS
```

Maximum number of hooks that can be registered

_adding more hooks is a bad practice, this constant limits potential gas costs for multi-hook execution, creates a soft protection against DOS issues caused by hook misconfiguration._

### HookAlreadyRegistered

```solidity
error HookAlreadyRegistered(address hook)
```

_Reverts when `addHook` is called with a hook already in the registry._

### HookNotRegistered

```solidity
error HookNotRegistered(address hook)
```

_Reverts when `removeHook` is called with a hook not in the registry._

### ZeroAddress

```solidity
error ZeroAddress()
```

_Reverts when an address argument is the zero address._

### MaxHooksExceeded

```solidity
error MaxHooksExceeded()
```

_Reverts when adding a hook would exceed `MAX_HOOKS`._

### SelfRegistrationNotAllowed

```solidity
error SelfRegistrationNotAllowed()
```

_Reverts when the container is asked to register itself as a sub-hook._

### HookVaultMismatch

```solidity
error HookVaultMismatch(address hook)
```

_Reverts when the candidate hook's `vault()` does not match this container's vault._

### OnlyVault

```solidity
error OnlyVault()
```

_Reverts when a forwarding hook entry point is called by any address other than `VAULT`._

### addHook

```solidity
function addHook(address _hook) external
```

Adds a hook to the container

_Only callable by accounts with HOOK_MANAGER_ROLE
IMPORTANT: This function assumes _hook implements IHook interface correctly.
     No interface validation is performed. Adding an invalid hook will cause
     all vault operations to revert. Callers must verify hook compatibility externally._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| _hook | address | The address of the hook contract to add |
