## HookContainer

Container that aggregates multiple `IHook` implementations into a single
        hook the vault can call. Forwards every pre/post hook call to each
        registered sub-hook sequentially; a revert from any sub-hook aborts the
        enclosing vault operation. Uses ERC-7201 namespaced storage for isolation
        and `AccessControlDefaultAdminRulesEnumerable` for role-based admin.

_Hook order is NOT guaranteed to remain stable: `addHook` appends, but
     `removeHook` uses swap-and-pop. Sub-hooks must be independently valid and
     must not rely on a specific execution ordering.
Trust model: this container implicitly trusts all registered hook code.
     Sub-hooks should be stateless validators, should not enable callbacks or
     arbitrary code execution, and should be thoroughly audited before
     registration. The container intentionally has no reentrancy protection and
     performs no caller verification — hook entry points are publicly callable.
     A malicious or buggy sub-hook can block all vault operations._

### MAX_HOOKS

```solidity
uint256 MAX_HOOKS
```

Maximum number of hooks that can be registered in the container.

_Adding more hooks is a bad practice; this constant limits gas costs for multi-hook
     execution and creates a soft protection against DOS caused by hook misconfiguration._

### HookAlreadyRegistered

```solidity
error HookAlreadyRegistered(address hook)
```

_Fires when `addHook` is called with an address already in the registry._

### HookNotRegistered

```solidity
error HookNotRegistered(address hook)
```

_Fires when `removeHook` is called with an address not in the registry._

### ZeroAddress

```solidity

```

### MaxHooksExceeded

```solidity
error MaxHooksExceeded()
```

_Fires when `addHook` would exceed `MAX_HOOKS` registered entries._

### SelfRegistrationNotAllowed

```solidity
error SelfRegistrationNotAllowed()
```

_Fires when the container is asked to register itself as a sub-hook._

### constructor

```solidity
constructor(address _admin) public
```

Deploys the hook container and grants `DEFAULT_ADMIN_ROLE` to `_admin`.
        `HOOK_MANAGER_ROLE` is admined by `DEFAULT_ADMIN_ROLE`.

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| _admin | address | The admin address that can manage roles. Zero-address check is               handled by the `AccessControlDefaultAdminRulesEnumerable` constructor. |

### addHook

```solidity
function addHook(address _hook) external
```

Registers a new sub-hook with the container. Callable only by
        accounts with `HOOK_MANAGER_ROLE`.

_This function assumes `_hook` implements the `IHook` interface correctly.
     No interface validation is performed. Adding an invalid hook will cause
     all vault operations to revert. Callers must verify hook compatibility externally._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| _hook | address | The address of the hook contract to register. |

### removeHook

```solidity
function removeHook(address _hook) external
```

Removes a sub-hook from the container. Callable only by accounts
        with `HOOK_MANAGER_ROLE`. Order of remaining hooks may change
        because removal uses swap-and-pop.

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| _hook | address | The address of the hook contract to remove. |
