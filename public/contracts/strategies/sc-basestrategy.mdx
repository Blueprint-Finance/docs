## BaseStrategy

Abstract base strategy that wires a strategy implementation to a single vault.
        Provides shared functionality for fund allocation, deallocation, withdrawal,
        pausing, role-based access control, and the maximum-withdraw limit. Concrete
        strategies inherit this contract and implement the position-management hooks.

_Uses EIP-7201 storage layout for upgradeability._

Internal initializer that wires the strategy to its admin and bound vault.

_Sets role admins, grants the initial role set, and reads the underlying asset
     from the vault. Callable only by child initializers._

| ---- | ---- | ----------- |

### allocateFunds

```solidity
function allocateFunds(bytes data) external virtual returns (uint256)
```

Allocate funds from the bound vault into the underlying protocol.

_Invoked by the vault when capital is being deployed. Implementations MUST emit the
     `AllocateFunds` event and MUST revert if the full requested amount cannot be deposited
     (e.g. allocation cap reached, slippage exceeded, protocol-side rejection). Most
     implementations require the strategy to be pre-approved for the vault's asset._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| data | bytes | Strategy-specific calldata (e.g. slippage tolerance, routing parameters). |

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| [0] | uint256 | The amount of underlying assets that were successfully allocated. |

### deallocateFunds

```solidity
function deallocateFunds(bytes data) external virtual returns (uint256)
```

_Invoked by the vault when capital is being unwound. Implementations MUST emit the

| Name | Type | Description |

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| [0] | uint256 | The amount of underlying assets that were successfully returned to the vault. |
