## BaseLoopingStrategy

Abstract base for leveraged ("looping") strategies. Adds leverage adjustment,
        target-LTV maintenance, and flash-loan-assisted position management on top of
        the standard strategy lifecycle.

_Concrete looping strategies inherit this contract; it combines `LoopingPrimitive`
     and `BaseStrategy`._

### onlyAdminOrOperatorWhenNotPaused

```solidity
modifier onlyAdminOrOperatorWhenNotPaused()
```

_Restricts function access: while paused, only `STRATEGY_ADMIN` may call;
     while unpaused, both `STRATEGY_ADMIN` and `OPERATOR_ROLE` may call._

### _allocateToPosition

```solidity
function _allocateToPosition(bytes data) internal virtual returns (uint256)
```

_Allocates funds into the position. When looping is disabled, supplies the
     tokens directly to the lender. When looping is enabled, prepares loop
     parameters and runs a leverage operation, then stages any leftover floating
     collateral via the lender staging interface._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| data | bytes | ABI-encoded `uint256` allocation amount. |

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| [0] | uint256 | The actual amount allocated. |

### _deallocateFromPosition

```solidity
function _deallocateFromPosition(bytes data) internal virtual returns (uint256)
```

_Deallocates funds from the position. When the amount is `type(uint256).max`,
     uses the previewed position value as the target. When looping is disabled,
     withdraws directly from the lender; otherwise runs a leverage deallocation
     operation. If the operation is a max withdraw, the stored target LTV and
     deviation are cleared._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| data | bytes | ABI-encoded `uint256` deallocation amount; `type(uint256).max` means        deallocate the full position. |

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| [0] | uint256 | The actual amount deallocated. |

### _withdrawFromPosition

```solidity
function _withdrawFromPosition(uint256 assets) internal virtual returns (uint256)
```

_Services a user withdrawal. If looping is disabled, withdraws directly from
     the lender. Otherwise, executes a plain withdraw when it keeps the LTV inside
     bounds, or runs a full leverage operation. Small-withdraw plain operations
     mitigate atomic loss attacks that would otherwise force a flash-loan loop._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| assets | uint256 | The amount of assets to withdraw. |

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| [0] | uint256 | The actual amount withdrawn. |

### adjustLeverage

```solidity
function adjustLeverage() external virtual
```

Permissionlessly adjusts leverage back toward the stored target LTV.

_Requires looping to be enabled and `permissionedLtvAdjustment` to be `false`.
     Reverts with `LtvWithinBounds` if the current LTV is already inside the
     target band; otherwise executes a leverage operation using the stored
     slippage tolerance._

### adjustLeverage

```solidity
function adjustLeverage(uint64 maxSlippageInWad, uint64 targetLtvInWad, bool setNewTargetLtv) external virtual
```

Permissioned leverage adjustment with caller-supplied slippage and target LTV.

_Callable by `STRATEGY_ADMIN` (always) or `OPERATOR_ROLE` (when not paused).
     When `setNewTargetLtv` is `true` the supplied `targetLtvInWad` is persisted
     using the stored deviation; when `false` the call adjusts toward
     `targetLtvInWad` for this transaction only and reverts if it would exceed
     the lender's maximum LTV._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| maxSlippageInWad | uint64 | Slippage tolerance for this adjustment, in WAD. |
| targetLtvInWad | uint64 | Target LTV to adjust toward, in WAD. |
| setNewTargetLtv | bool | If `true`, also persists `targetLtvInWad` as the stored target. |

### previewOperation

```solidity
function previewOperation(uint256 allocOrDeallocAmount, bool isAllocation, uint64 targetLtvInWad, uint64 maxSlippageInWad) public view returns (struct PreviewOperationResult result, bool ltvUpperBoundReached, bool deallocationHigherThanEquity, bool insufficientFlashLiquidity)
```

Previews an allocation or deallocation without executing it.

_Returns the leverage figures (flash amount, paired-token amount, equity
     before/after, maximum loss) together with three error flags so a caller
     can decide whether the operation is feasible. Equity values include the
     lender module's staged liquidity. If `targetLtvInWad` exceeds `WAD` the
     function short-circuits with `ltvUpperBoundReached = true`._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| allocOrDeallocAmount | uint256 | The amount to allocate or deallocate. |
| isAllocation | bool | `true` to preview an allocation, `false` for a deallocation. |
| targetLtvInWad | uint64 | Target LTV the operation should reach, in WAD. |
| maxSlippageInWad | uint64 | Slippage tolerance for the operation, in WAD. |

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| result | struct PreviewOperationResult | The full preview result struct, including flash and swap sizing         and the resulting equity delta. |
| ltvUpperBoundReached | bool | `true` when the upper LTV bound would be breached. |
| deallocationHigherThanEquity | bool | `true` when the requested deallocation         exceeds the position equity. |
| insufficientFlashLiquidity | bool | `true` when the available flash liquidity is         insufficient for the operation. |

### enableLooping

```solidity
function enableLooping(address flashModule_, address swapModule_, uint64 targetLtvInWad, uint256 flashCollateralEpsilon_, uint64 ltvAdditiveDeviationInWad, uint64 maxSlippageInWad, bool permissionedLtvAdjustment_) external virtual
```

Enables looping with the supplied module wiring and LTV/slippage parameters.

_Callable only by `STRATEGY_ADMIN`. Reverts if looping is already enabled or
     if any of `targetLtvInWad`, `ltvAdditiveDeviationInWad`, or
     `flashCollateralEpsilon_` is zero. Emits `LoopingEnabled`._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| flashModule_ | address | Address of the flash loan module to bind. |
| swapModule_ | address | Address of the swap module to bind. |
| targetLtvInWad | uint64 | Target LTV the strategy should maintain, in WAD. |
| flashCollateralEpsilon_ | uint256 | Minimum flash collateral epsilon used in operation        sizing. |
| ltvAdditiveDeviationInWad | uint64 | Permitted additive deviation around the target        LTV, in WAD. |
| maxSlippageInWad | uint64 | Default slippage tolerance, in WAD. |
| permissionedLtvAdjustment_ | bool | If `true`, only admins/operators may call        `adjustLeverage`; if `false`, leverage adjustment is permissionless. |
