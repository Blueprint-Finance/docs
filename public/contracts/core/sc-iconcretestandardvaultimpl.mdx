## IConcreteStandardVaultImpl

Interface for the standard vault implementation that manages multiple investment strategies.

_This interface extends the base tokenized vault functionality with strategy management capabilities.
     Strategies are external contracts that implement the `IStrategyTemplate` interface and handle
     fund allocation to different yield-generating protocols or investment opportunities._

### StrategyStatus

_Enumeration of possible strategy statuses within the vault.
Inactive: Strategy is inactive and cannot receive new allocations.
Active: Strategy is active and can receive allocations and process withdrawals normally.
Halted: Strategy is halted, typically due to detected issues or failures.
In this state, the strategy can be removed even if it has allocated funds_

```solidity
enum StrategyStatus {
  Inactive,
  Active,
  Halted
}
```

### toggleStrategyStatus

```solidity
function toggleStrategyStatus(address strategy) external
```

Toggles a strategy's status between Active and Halted.

_This is a safety mechanism to isolate problematic strategies or reactivate previously halted ones.
Active strategies can receive allocations and participate in yield accrual and withdrawal operations.
Halted strategies are skipped during yield accrual and withdrawal operations.
Only callable by accounts with the STRATEGY_MANAGER role._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| strategy | address | The address of the strategy contract to toggle. Requirements: - Strategy must exist in the vault - Strategy must be either Active or Halted (cannot toggle Inactive strategies) - Caller must have STRATEGY_MANAGER role Emits: - StrategyStatusToggled event Reverts: - StrategyDoesNotExist if strategy is not in the vault |

### allocate

```solidity
function allocate(bytes data) external
```

Executes fund allocation and deallocation operations across multiple strategies.

_This function performs a yield accrual operation first to update vault accounting,
     then executes the allocation operations specified in the data parameter.
All operations are performed via delegatecall to the respective modules to maintain
     proper storage context and access control.
Only callable by accounts with the ALLOCATOR role.
The function automatically triggers yield accrual before allocation to ensure
        accurate vault accounting prior to fund movements._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| data | bytes | ABI-encoded array of AllocateParams structures containing the allocation             operations to execute. Each param specifies whether to allocate or deallocate             funds, which strategy to use, and any additional data required by the strategy. |

### accrueYield

```solidity
function accrueYield() external
```

Accrues yield and accounts for losses across all active strategies in the vault.

_This function updates the vault's internal accounting by querying the current
     value of all strategy allocations and calculating net yield or losses.
This function can be called by anyone to update the vault's accounting.
The yield accrual operation does not trigger actual fund movements, it only
        updates the vault's internal state to reflect current strategy values._

### previewAccrueYield

```solidity
function previewAccrueYield() external view returns (uint256, uint256)
```

Previews the total assets that would be available after accruing yield from all strategies.

_This function simulates the yield accrual operation without actually executing it,
     providing a view of what the vault's total assets would be after accounting
     for yield and losses across all active strategies.
The calculation includes the current lastTotalAssets plus any positive
     yield minus any losses that would be realized during yield accrual.
This is a view function that does not modify state or trigger any actual
     fund movements or strategy interactions._

#### Return Values

| Name | Type | Description |
| ---- | ---- | ----------- |
| [0] | uint256 | The total amount of assets that would be available in the vault after yield accrual,         denominated in the vault's underlying asset token. |
| [1] | uint256 | The total amount of shares that would be available in the vault after yield accrual,         calculated as current totalSupply + management fee shares. |
