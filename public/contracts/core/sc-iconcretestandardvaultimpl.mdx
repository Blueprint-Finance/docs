## IConcreteStandardVaultImpl

Standard ERC-4626 vault implementation that manages a set of pluggable strategies,
        each of which deploys capital into an external yield-generating protocol.

_Extends the upgradeable-vault, ERC-4626, and access-control surfaces with strategy
     management (add/remove/halt), batched allocation, yield accrual, fee configuration,
     deposit/withdraw limits, hook configuration, hurdle-rate gating, and deallocation ordering.
     Strategies must implement `IStrategyTemplate` and share the vault's underlying asset._

### StrategyStatus

_Possible operational statuses of a strategy within the vault.
     `Inactive` — unregistered/unknown to the vault.
     `Active` — eligible for allocations, yield accrual, and withdrawals.
     `Halted` — skipped during yield accrual and withdrawals; may be removed even if
     it still has allocated funds (intended for emergency isolation)._

```solidity
enum StrategyStatus {
  Inactive,
  Active,
  Halted
}
```

### StrategyData

_Per-strategy metadata tracked by the vault: current operational `status` and the
     total vault assets allocated to the strategy, denominated in the vault's underlying asset._

```solidity
  uint120 allocated;
}
```

### addStrategy

```solidity
function addStrategy(address strategy) external
```

Register a new strategy with the vault.

_The strategy must implement `IStrategyTemplate` and report the same underlying
     asset as the vault. Only callable by accounts with the STRATEGY_MANAGER role.
     Emits `StrategyAdded` on success; reverts with `InvalidStrategyAsset` if the
     assets do not match or `StrategyAlreadyAdded` if the strategy is already registered._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| strategy | address | Address of the strategy contract to add. |

### removeStrategy

```solidity
function removeStrategy(address strategy) external
```

Remove a previously registered strategy from the vault.

_The strategy must have zero allocated funds, unless it is currently `Halted`,
     in which case it may be removed even with outstanding allocation. Only callable
     by accounts with the STRATEGY_MANAGER role. Emits `StrategyRemoved` on success;
     reverts with `StrategyDoesNotExist` if the strategy is unknown._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| strategy | address | Address of the strategy contract to remove. |

### toggleStrategyStatus

```solidity
function toggleStrategyStatus(address strategy) external
```

Toggle a strategy's status between `Active` and `Halted`.

_Halted strategies are skipped during yield accrual and withdrawals; the toggle
     is the primary mechanism for isolating problematic strategies and reactivating
     them later. Only callable by accounts with the STRATEGY_MANAGER role. `Inactive`
     strategies cannot be toggled. Emits `StrategyStatusToggled` on success and
     reverts with `StrategyDoesNotExist` if the strategy is unknown._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| strategy | address | Address of the strategy contract to toggle. |


Execute a batch of allocation and deallocation operations across vault strategies.

_Triggers a yield accrual before executing the batch so accounting is current.
     Operations are dispatched via delegatecall into the allocate module to preserve
     storage context and access control. Only callable by accounts with the ALLOCATOR role._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| data | bytes | ABI-encoded `AllocateParams[]` describing each allocation/deallocation leg. |

### accrueYield

```solidity
function accrueYield() external
```

Accrue yield and absorb losses across all active strategies, updating internal accounting.

_Permissionless — anyone may call. The accrual reads each strategy's reported
     allocated value, computes the net delta versus tracked allocation, and updates
     cached totals. No funds are moved; only accounting state changes._
