## IConcreteFactory

Factory that approves vault implementations, deploys CREATE2-deterministic vault proxies,
        tracks per-vault upgrade/migration paths, and stores the protocol-wide enforced default
        configuration (e.g. fee recipients) applied to newly created vaults.

_Implementations expose: implementation approval/blocking, migration path declarations,
     proxy deployment with optional caller-provided salts, address prediction, single and batch
     vault upgrades, vault registration for externally deployed vaults, and getters for the
     current implementation registry and default vault configuration._

### upgrade

```solidity
function upgrade(address vault, uint64 newVaultImpl, bytes data) external
```

Upgrade a vault to a new implementation ID.

_Only the vault's owner can initiate the upgrade. `newVaultImpl` must be strictly
     greater than the vault's current implementation ID._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| vault | address | Address of the vault to upgrade. |
| newVaultImpl | uint64 | Target vault implementation ID. |
| data | bytes | Upgrade calldata forwarded to the new implementation's upgrade routine. |

### batchUpgrade

```solidity
function batchUpgrade(address[] vaultAddresses, uint64 newVaultImpl, bytes[] data) external
```

Upgrade a set of vaults to the same new implementation ID in a single transaction.

_The caller must own every vault in `vaultAddresses`, and `newVaultImpl` must be
     strictly greater than each vault's current implementation ID._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| vaultAddresses | address[] | Vaults to upgrade. |
| newVaultImpl | uint64 | Target vault implementation ID applied to every vault. |
| data | bytes[] | Per-vault upgrade calldata (one entry per vault). |
