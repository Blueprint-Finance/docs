## IConcreteAsyncVaultImpl

Async vault that augments the standard vault with epoch-based withdrawal queueing.

_Implementations queue user withdrawal requests inside a per-vault epoch lifecycle:
     requests submitted while an epoch is `Active` are aggregated; once the epoch is closed
     it transitions to `Processing`; when an allocator processes it a share price is locked
     and the epoch becomes `Processed`, after which depositors can claim their assets.
     The interface adds the corresponding lifecycle entry points (cancel, claim, close,
     process, move to next epoch) and a priority-withdrawal path used during early unwinds._

### EpochState

_Lifecycle states of a withdrawal epoch._

```solidity
enum EpochState {
  Inactive,
  Active,
  Processing,
  Processed
}
```

### claimPriorityWithdrawal

```solidity
function claimPriorityWithdrawal(address user, uint256 sharesToFulfil, uint256 unwindCost, address strategy) external
```

Claim a priority withdrawal.

_Only callable by PRIORITY_WITHDRAWAL_EXECUTOR role.
     Burns the user's queued shares, transfers `grossAssets - unwindCost` to the
     user, deducts the net amount from `cachedTotalAssets`, and calls `IAsyncAccounting.adjustTotalAssets`
     on the strategy to record the unwind cost.  The next yield accrual will
     reconcile the vault's tracked allocation with the strategy._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| user | address | The user address to claim from. |
| sharesToFulfil | uint256 | The number of shares to burn. |
| unwindCost | uint256 | The cost charged for early unwinding. |
| strategy | address | The strategy whose `totalAllocatedValue` will be reduced by the                 unwind cost. Must not be `address(0)`. |

### closeEpoch

```solidity

```

Close the current active epoch and advance the epoch counter.

_Only callable by accounts with the WITHDRAWAL_MANAGER role. The previous epoch
     must already be processed before a new close can succeed._

### processEpoch

```solidity
function processEpoch() external
```

Process pending redeem requests for the next unprocessed closed epoch.

_Harvests all strategies first so the locked share price reflects current accounting,
     then computes the share price and reserves the assets required to satisfy the epoch.
     Only callable by accounts with the ALLOCATOR role._
