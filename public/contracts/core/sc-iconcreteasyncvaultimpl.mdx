## IConcreteAsyncVaultImpl

Interface for the async vault implementation that provides epoch-based withdrawal management,
        extending the standard vault with queued, batched, and priority withdrawal capabilities.

_Users submit withdrawal requests that are queued in epochs, processed by allocators when liquidity
     is available, and then claimed by users after processing is complete._

```solidity
enum EpochState {

  Active,
  Processing,

}
```

### claimPriorityWithdrawal

```solidity
function claimPriorityWithdrawal(address user, uint256 sharesToFulfil, uint256 unwindCost, address strategy) external
```

Claim a priority withdrawal.

_Only callable by PRIORITY_WITHDRAWAL_EXECUTOR role.
     Burns the user's queued shares, transfers `grossAssets - unwindCost` to the
     user, deducts the net amount from `cachedTotalAssets`, and calls `IAsyncAccounting.adjustTotalAssets`
     on the strategy to record the unwind cost.  The next yield accrual will
     reconcile the vault's tracked allocation with the strategy._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| user | address | The user address to claim from. |
| sharesToFulfil | uint256 | The number of shares to burn. |
| unwindCost | uint256 | The cost charged for early unwinding. |
| strategy | address | The strategy whose `totalAllocatedValue` will be reduced by the                 unwind cost. Must not be `address(0)`. |

```solidity

```

Process all pending redeem requests for a specific epoch

### processPartialEpochRequest

```solidity
function processPartialEpochRequest(address user, uint256 epochID, uint256 amount) external
```

Fulfil all or part of a user's withdrawal request from a closed,
        unprocessed epoch.

_Burns the specified shares at the current exchange rate and transfers the
     corresponding assets immediately (no separate claim step).  The epoch is
     NOT marked as processed; `processEpoch()` must still be called to
     finalise the epoch.
Only callable by WITHDRAWAL_MANAGER role._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| user | address | The user whose closed-epoch request to fulfil. |
| epochID | uint256 | The closed epoch to target. Must be closed and not yet processed                (intent-validation parameter). |
| amount | uint256 | Number of shares to process. Pass `type(uint256).max` to process               the user's entire request. |

### moveRequestToNextEpoch

```solidity
function moveRequestToNextEpoch(address user, uint256 fromEpochID, uint256 amount) external
```

Move a user's withdrawal request from the closed, unprocessed epoch
        (`latestEpochID - 1`) to the current active epoch (`latestEpochID`).

_Reverts with `EpochMismatch` if `fromEpochID` does not match
     `latestEpochID - 1`, or with `EpochAlreadyProcessed` if the
     previous epoch is already processed.
Only callable by WITHDRAWAL_MANAGER role._

#### Parameters

| Name | Type | Description |
| ---- | ---- | ----------- |
| user | address | The user address whose request to move. |
| fromEpochID | uint256 | The closed epoch to move from. Must equal `latestEpochID - 1`                    (intent-validation parameter). |
| amount | uint256 | Number of shares to move. Pass `type(uint256).max` to move the               user's entire request. |
